# 외교 대화 10회 및 호의 보상 — 2026-10-16

## 사용자 결정

- 사용자 발언과 상대 답변 한 쌍을 1회로 센다. 일반 외교 통신과 만찬은 최대 10회로 마무리한다.
- 긍정적인 기분 변화 1번에 호의 1점, 부정적인 변화 1번에 -1점. 큰 변화도 횟수 1번으로 센다. 중립은 0점.
- 종료 때 합계에서 최소 0/최대 5개를 지급한다. 부정적인 변화가 기존 보유 호의를 빼앗지는 않는다.
- 플레이어가 상대 제국에 행사할 수 있는 호의로 지급한다.

## 구현

- 일반 외교는 10번째 응답 뒤 자동 정산·입력 종료. AI/전송 오류는 정상 발언 횟수에 포함하지 않는다. 새 통신 연결 시 회차를 초기화한다. 기존 수동 대화 종료 버튼은 일찍 종료할 때도 적립분을 정산한다.
- 일반 외교의 기존 호감 변화 일괄 처리를 유지하고, 별도의 호의 정산을 추가했다. 마지막 발언에서 생긴 수락 대기 제안은 그대로 수락/거절할 수 있다.
- 만찬은 응답을 say/mood JSON으로 받아 방문별 기록에 기분 단계를 함께 저장한다. 10회 뒤 정산한다. 창을 중간에 닫으면 대화를 보존하고, 같은 방문에서 이어간다. 시연은 계산만 하고 실제 지급하지 않는다.
- 기존 만찬의 옛 발언은 회차에 포함하지만 mood가 없으면 0점으로 취급한다. 이미 10회 이상 진행된 옛 기록에 소급 보상하지 않는다.
- 지급은 게임 문서의 add_favors, num_favors를 사용한다. 상대 국가 스코프 안의 prev 블록에서 플레이어에게 target=prev(상대 제국) 방향으로 지급한다.
- 지급 전후 수량을 읽어 FAVORS 응답으로 출력하고, 요청 번호·대화 식별자·세이브·상대가 맞는 경우에만 획득 확인을 표시한다. 게임 한도 등으로 증가량이 적으면 실제 증가량만 표시한다.
- AppData/sllm_favor_grants.json에 지급 요청을 먼저 기록한다. 게임에도 대화별 고유 변수로 재적용을 막는다. 응답 불명·중복·세이브 변경에서는 자동 재전송하지 않는다. 여러 정산 요청은 순차 처리한다.
- 게임 파일을 새로 추가하는 방식이 아니므로 앱 재시작 후 적용한다. 게임 재시작은 이번 변경에 필요하지 않다.

## 검증과 한계

- 10회 상한, 11회 차단, 정상 외교 종료 시 1회 정산, 재정산 방지 검사 통과.
- 긍정/부정/중립 합산·0~5 상한 검사 통과.
- 명령 생성의 방향·세이브 가드·고유 지급 변수·인자 주입 방지 검사 통과.
- 지급 전후 응답 처리, 영속 기록으로 중복/불명 요청 재전송 방지, 세이브 변경 거부 검사 통과.
- HTML/JS 구문 검사와 TypeScript 빌드 통과. 전체 자체 검사 981개 통과, 기존 환경 탐색 문제 4개 실패.
- 실제 게임에서 num_favors 수량 읽기와 add_favors 지급 결과는 아직 새 대화를 마친 뒤 확인해야 한다. 모의 검사만으로 실게임 지급 성공을 주장하지 않는다.
