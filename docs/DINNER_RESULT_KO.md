# 지도자 초대·방문 준비 — 2026-10-16

## 사용 흐름

1. 외교 서신의 **지도자 초대하기** 버튼 → 초대장 작성 창에서 통신 가능한 제국을 선택하고 서신을 작성·발송.
2. 현재 게임 날짜로 **3~6개월 후** 답장 예약. 앱/게임을 계속 실행하고 새 MONTH 신호가 들어오면 처리. 현실 시간 타이머가 아님.
3. 현재 알려진 관계 점수·적대·라이벌·전쟁 상태로 수락 확률을 정하고, 선택한 Player2/개인 API와 공통 응답 언어로 답장 생성. 전쟁 중이면 거절. 친선 관계도 무조건 수락하는 것은 아님.
4. 기존 수신함에 수락/거절 서신 도착. 수락하면 **실제 답장 전달 시점부터 6개월 뒤** 방문 예약. 앱이 꺼져 있었거나 API 실패로 늦어진 답장을 과거에 전달한 것으로 취급하지 않음.
5. 방문일 이후 새 게임 월 신호에서 앱이 모드 도착 이벤트를 요청. 실제 게임 이벤트에서 접대 선택:
   - 성대하게 대접: 에너지 크레딧 **1,000** 소비.
   - 일반적으로 대접: 에너지 크레딧 **100** 소비.
   - 굴욕적으로 대접: 자원 소모 없음.
6. 모드의 선택 완료 신호를 받아 접대 방식을 기록하고 연대기에 남김. 만찬 대화창·접대에 따른 실제 관계 효과·만찬 후속 편지는 다음 확장 범위.

## 현재 제한과 보호 처리

- 첫 버전은 세이브/시간선마다 한 건의 진행 중인 초대만 허용. 예약 창에서 보낸 서신·답장 예정일·방문 예정일·진행 상태를 확인.
- 앱이 실행 중이어야 게임 월 신호를 읽어 답장과 방문 요청을 처리할 수 있음. 이미 열린 게임 이벤트와 자원 차감은 모드가 처리.
- 지도자가 바뀌면 초대를 취소. 방문 전 알려진 전쟁 상태, 실제 모드에서 통신 가능/전쟁 여부를 재검사. 연락처가 없으면 임의로 멸망했다고 판단하지 않고 갱신을 기다림.
- 시간선이 갈라지면 이전 분기의 변경 가능한 예약 상태를 자동 승계하지 않음. 다른 세이브/분기·로드 전 AI 응답을 반영하지 않음.
- AI 실패 시 예약 유지. 결정은 고정하고 다음 월에 편지 작성 재시도. 저장 실패 시 예약을 먼저 삭제하지 않음. 답장은 sourceId로 중복 저장 방지.
- 도착 전 예약을 arrival_requested로 저장. 응답 불확실 시 이벤트를 자동 재전송하지 않고 읽기 전용 상태 조회만 수행. 실제 선택 완료 신호 전에는 완료로 표시하지 않음.
- 자원은 초대나 답장 시점에 차감하지 않으며, 게임 옵션을 선택할 때만 모드에서 차감. 자원 부족 조건과 중복 차감 방지 플래그 포함.
- 현재 이벤트 설명은 초대한 제국의 지도자를 일반 문구로 표시. 초대 창/답장에는 대상 제국과 알려진 지도자 이름을 보관.
