# SLLM 콘솔 없는 게임 연결 (실험)

검증 대상: Stellaris Cygnus 4.5.2 (9776), Steam build 25664273, Windows x64.
실행 파일 SHA-256: 400DF27C82DDC845AA9DCE79BD468D81F18F060D299CD263E3AFA93AEF4F7A83.
다른 실행 파일에서는 내부 함수를 호출하기 전에 거부합니다.

앱이 요청마다 새 INI 파일을 게임 사용자 폴더에 만든 뒤 bridge-client.exe를 실행합니다.
클라이언트는 현재 게임의 프로세스와 창 스레드를 매번 찾습니다. 임시 메시지 후크를
이용해 그 스레드에서 게임의 run 처리 함수를 실행합니다. 요청마다 공유 메모리와
완료 이벤트를 새로 만들며, 완료 후 후크를 해제합니다. 클립보드, 창 활성화,
키보드 입력, 콘솔 열기/닫기를 사용하지 않습니다.

내부 run 반환은 전달 완료이고, 게임 행동의 성공 여부는 기존 SLLM:ACK가 결정합니다.
요청 번호, 대상 검증, 중복/오래된 요청 방지, 세이브별 기억 처리는 기존 앱·모드가
계속 담당합니다. 자동 재전송하지 않습니다. 완료가 불확실한 INI 파일은 보존합니다.

사용 방법: 앱을 다시 실행합니다. 기본 전달 방식은 DLL 연결입니다.
진단 목적으로만 SLLM_LEGACY_CONSOLE=1 환경변수를 지정하면 예전 입력 경로를 사용합니다.
DLL 연결 실패 시 예전 콘솔 경로로 자동 전환하지 않습니다.

이 실험의 확인 사항:
- 콘솔 닫힘 상태에서 run .ini 및 게임 로그 출력
- 기존 에너지 교환 효과와 ACK result=1, dup, stale
- 게임을 재시작한 뒤 연결 정보 재탐색

계속 검증할 사항: 플레이 중 다양한 행동, 세이브 재로드, 종료 및 장시간 사용.
창 메시지 처리 시점은 이번 명령에서 작동한 실행 경로이며 모든 게임 행동에 대한
스레드 안전성이 보장됐다는 의미는 아닙니다. 업데이트 시 주소와 호출 규약 재검증 필요.

빌드 소스는 src/에 있습니다. llvm-mingw x86_64 도구로 빌드합니다.
DllMain은 작업하지 않습니다. 명령은 임시 후크 콜백에서만 처리합니다.
